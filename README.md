# MatchWatch

Свайп-подбор фильмов для одного и для пары: Telegram Mini App как основная
платформа плюс полноценная десктопная веб-версия.

Совпали оба — фильм попадает в общий список «к просмотру», и вечер спасён.

---

## Что внутри

| Возможность | Как это работает |
|---|---|
| **Свайп-лента** | Жест, кнопки и клавиатура. Карточка объясняет, почему она здесь, и открывает описание по нажатию. |
| **Модель решений** | Влево — «мимо», вправо — «хочу посмотреть», глаз — «смотрел», звезда — «избранное». Любое решение убирает фильм из выбора навсегда; последнее можно отменить. |
| **Каталог с фильтрами** | Весь TMDB с фильтром по рейтингу, жанру, году и поиском — когда хочется выбрать самому, а не свайпать. |
| **Рекомендации по темам, а не по жанрам** | У каждого тайтла вектор весовых тегов из TMDB keywords + правила обогащения. Лайкая самурайское кино, вы поднимаете кластер `samurai / feudal-japan / honor-duty`, а не абстрактный «боевик». |
| **5D-настроение (Cine-Moods)** | Энергия · Мрак · Интеллект · Эмоциональность · Динамизм. Выводится из тегов, видно в профиле паутинкой. |
| **Совместные комнаты** | 4-значный код, присутствие через Realtime Presence, голос и мэтч одной транзакцией Postgres, празднование с конфетти, звуком и хаптикой. |
| **Три входа в комнату** | Ручной код, ссылка `?room=CODE`, Telegram deep-link `?startapp=CODE` — все через один нормализатор. |
| **Star Hub** | Актёры собираются из составов популярных фильмов, а не из рейтинга TMDB: тот ранжирует по кликам на сайте и выдаёт случайных людей с именами в оригинальном написании. Профиль с фактами и фильмографией, колода из его фильмов в один тап. |
| **Только вышедшее** | Анонсы и премьеры будущих месяцев отсекаются везде — в ленте, каталоге и поиске. Продукт отвечает на вопрос «что посмотреть сегодня», а трейлер посмотреть нельзя. |
| **Коллекция** | Каталог, «Моё» (желаемое · просмотрено · избранное · мэтчи · комната) и Звёзды в одной вкладке. |
| **Кино-рулетка** | Слот-машина для спонтанного вечера, без свайпов. |
| **Метрики и алерты** | Дашборд D1/D7, доля мэтчей, приглашения на пользователя; топ-5 ошибок; алерт в Telegram при всплеске. |

## Стек

- **Фронтенд** — React 19, Vite, собственная CSS-система (OLED-палитра, дизайн-язык «Neon Noir»)
- **Иконки и анимации** — Phosphor Icons, Canvas Confetti, Web Audio API (звук синтезируется, файлов нет)
- **Бэкенд** — серверлес-функции Vercel в `api/`, без тяжёлых SDK: HMAC и Sentry-envelope на встроенном `node:crypto`
- **Данные** — Supabase: Postgres, Realtime, Auth и RLS
- **Каталог** — TMDB API, всегда через серверный прокси
- **Хостинг** — Vercel

### Ключевые решения

**Внутренний `user_id` не привязан к способу входа.** Telegram-id и email — это
записи в таблице `identities`, указывающие на один и тот же `auth.users.id`.
Связать два способа входа в один профиль — значит добавить строку, а не
мигрировать данные.

**Вход через Telegram не требует секретного ключа Supabase.** Сервер проверяет
подпись `initData` секретом бота и выводит из `telegram_id` детерминированные
учётные данные: `HMAC(bot_token, "mw-auth:" + id)`. Угадать пароль нельзя, не
зная токена бота, а токен живёт только на сервере. Профиль и связку заполняет
триггер в базе — серверу не нужно писать в таблицы вовсе.

**Подтверждение почты выключено осознанно.** Основной вход — Telegram, email
нужен как логин. Встроенный SMTP Supabase отдаёт пару писем в час, после чего
регистрация упирается в `over_email_send_rate_limit`, а войти нельзя — аккаунт
не подтверждён. Триггер `on_auth_user_autoconfirm` снимает это; компромисс
описан в самой миграции.

**Ключ TMDB живёт только на сервере.** Клиент ходит в `api/tmdb/*`; ответы
кэшируются в Postgres (списки — 6 часов, карточки — неделя), поэтому рейт-лимит
TMDB не зависит от числа свайпов.

**Два прохода по данным каталога.** Список отдаёт «лёгкие» тайтлы мгновенно
(теги из жанров), затем `api/tmdb/enrich` фоном подтягивает настоящие
`keywords` — карточка появляется сразу, а точность догоняет.

**Логика комнат живёт в SQL.** `record_swipe` берёт блокировку строки комнаты и
одной транзакцией пишет голос, считает кворум и создаёт мэтч. Без блокировки два
последних голоса, поданных одновременно, под READ COMMITTED не видят друг друга:
каждый насчитывает меньше кворума, и мэтч не рождается вовсе.

**Лента не кончается.** Каталог отдаёт до 500 страниц, и колода
дозагружается порциями: очередь опускается до восемнадцати карточек —
подтягивается следующая пачка. Тонкость в том, что страница целиком может
состоять из уже решённых фильмов: прирост пула есть, а показывать нечего.
Поэтому дозагрузка тянет страницы, пока не наберёт именно *новых* карточек,
а «колода закончилась» показывается только когда исчерпаны страницы каталога.
Пока пачка едет, финального экрана не видно — вместо него индикатор.

**Колода ждёт историю решений.** Сборка не начинается, пока не приехали
`title_history` и профиль вкуса. Иначе исключать нечего: движок собирает
ленту с пустой историей, и всё отклонённое возвращается. Отличать «истории
нет» от «решений нет» здесь принципиально — тест `B27` фиксирует разницу.

**Первая карточка не ждёт весь пул.** Полный набор кандидатов — полтора
десятка последовательных запросов; на мобильном это секунды пустого экрана.
Поэтому набор двухстадийный: сначала минимум для первой колоды, остальное
догружается фоном.

**Прогресс в комнате не хранится локально.** Что я уже отсвайпал — записано в
`room_swipes` на сервере. Свернули Telegram, вернулись — состояние на месте,
потому что терять было нечего.

**Десктоп — не растянутая мобилка.** Кнопка во всю строку уместна под палец, но
на полутора тысячах пикселей превращается в полосу через экран. В студии колонка
контента ограничена, формы и кнопки — тоже, а сетки постеров, наоборот, берут всю
ширину.

## Запуск

### 1. Зависимости

```bash
npm install
```

### 2. Переменные окружения

```bash
cp .env.example .env
```

Что где взять:

| Переменная | Где взять | Без неё |
|---|---|---|
| `TMDB_ACCESS_TOKEN` (или `TMDB_API_KEY`) | [themoviedb.org → Settings → API](https://www.themoviedb.org/settings/api) | Каталог отдаёт `503 tmdb_not_configured`, лента показывает ошибку с повтором |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | Supabase → Project Settings → API | Приложение уходит в локальный режим: личная лента работает, комнаты нет |
| `TELEGRAM_BOT_TOKEN` | [@BotFather](https://t.me/BotFather) | Вход через Telegram отключён — подпись `initData` проверить нечем |
| `VITE_TELEGRAM_BOT_USERNAME`, `VITE_TELEGRAM_APP_NAME` | @BotFather → ваш Mini App | Ссылки-приглашения деградируют до обычного `?room=CODE` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API keys | Вход и комнаты работают. Отключаются серверные задачи: кэш каталога, журнал телеметрии, дашборд, крон уборки комнат |
| `SENTRY_DSN`, `VITE_SENTRY_DSN` | Sentry (бесплатный тариф) или совместимый сервис | Трекинг молча выключается, приложение работает |
| `ALERT_TELEGRAM_CHAT_ID` | id чата, куда бот шлёт алерты | Всплески ошибок никуда не уходят |
| `OPS_DASHBOARD_TOKEN`, `CRON_SECRET` | придумайте случайные строки | Дашборд и крон-эндпоинты открыты |

### 3. Разработка

```bash
npm run dev
```

Плагин `devServerApi.js` обслуживает `api/` прямо в Vite — локально работает
полный стек, включая серверные переменные из `.env`.

### 4. Тесты

```bash
npm test
```

### 5. Сборка

```bash
npm run build
```

## Развёртывание

### Supabase

Схема, RLS-политики и вся доменная логика комнат лежат в `supabase/migrations`
и уже применены к проекту. Воспроизвести с нуля:

```bash
supabase link --project-ref <ваш-ref>
supabase db push
```

Что гарантируют политики: `profiles` пишет только владелец, `access_tier` и
`access_stars` — вообще не с клиента (право `UPDATE` выдано точечно на три
безобидные колонки); `catalog` и `app_config` доступны только на чтение; голос
в комнате может поставить лишь сам участник; таблицы `identities` и `ops_*`
недоступны клиенту ни на чтение, ни на запись.

Проверить состояние после изменений:

```bash
supabase inspect db
```

### Vercel

Проект деплоится как есть: `vercel.json` уже описывает сборку, `api/` и два крона.

```bash
vercel --prod
```

Не забудьте перенести переменные окружения в настройки проекта (серверные — без
префикса `VITE_`, они не попадут в бандл).

Кроны:
- `/api/ops/rooms-gc` — ежечасно, TTL-уборка комнат (4-значных кодов конечное
  число, без уборки они начнут конфликтовать);
- `/api/ops/digest` — по понедельникам, сводка «топ-5 ошибок за неделю».

### Telegram Mini App

1. `@BotFather` → `/newbot` → скопировать токен в `TELEGRAM_BOT_TOKEN`.
2. `@BotFather` → `/newapp` → выбрать бота, указать URL деплоя на Vercel,
   задать короткое имя приложения.
3. Заполнить `VITE_TELEGRAM_BOT_USERNAME` и `VITE_TELEGRAM_APP_NAME` — из них
   собирается ссылка-приглашение `t.me/<bot>/<app>?startapp=CODE`.

Что приложение делает внутри Telegram само:

- синхронизирует тему с `themeParams` клиента и красит шапку в чёрный;
- запрашивает `requestFullscreen` на Bot API 8.0+, иначе просто `expand()`;
- подставляет `safeAreaInset` и `contentSafeAreaInset` в CSS-переменные,
  поэтому док не уезжает под системные элементы;
- ловит `start_param` и открывает комнату сразу после входа;
- включает подтверждение выхода, пока идёт сессия в комнате.

**Тактильный отклик** берётся из нативного `HapticFeedback`, а не из Web
Vibration: внутри TMA они ведут себя по-разному, а на iOS веб-вибрация не
работает вовсе. Проверять — на реальных клиентах, эмулятор здесь врёт.

**Вход** происходит автоматически: `initData` уходит на `/api/auth/telegram`,
там проверяется подпись HMAC секретом бота, и клиент получает учётные данные,
выведенные из `telegram_id`. Нажимать ничего не нужно.

## Модель решений

Ровно четыре решения, и каждое убирает фильм из выбора навсегда.

| Действие | Жест / кнопка | Куда попадает | Вес в профиле |
|---|---|---|---|
| Избранное | свайп вправо · ★ | «Моё → Избранное» | ×1 |
| Смотрел | 👁 | «Моё → Просмотрено» | ×0,2 |
| Желаемое | 🔖 | «Моё → Желаемое» | ×0,1 |
| Мимо | свайп влево · ✕ | никуда — в этом весь смысл | −0,1 |

Избранное — единица шкалы, потому что это главный жест: свайп вправо.
Просмотр весит впятеро меньше (посмотреть можно и по чужому совету), а
намерение посмотреть — вдесятеро: оно ещё не подтверждено опытом.

Порог отсечения слабых весов (`decay.pruneBelow`) обязан оставаться заметно
ниже самого слабого сигнала. Вклад тега равен весу действия, умноженному на
долю тега в фильме, а у второстепенных тегов эта доля 0,2–0,5. При пороге
выше слабого сигнала обучение стирается прямо в момент записи — молча и
незаметно. Тест `F8a` следит за этим соотношением.

Последнее решение отменяется кнопкой ↩ — карточка возвращается в колоду,
а профиль вкуса откатывается к снимку, снятому перед действием. Пересчитать
сигнал «в обратную сторону» нельзя: старение и масса настроения делают
`applySignal` необратимым, поэтому снимок честнее арифметики.

Дизлайки нигде не показываются списком намеренно: их единственное назначение —
исчезнуть. Нажатие на карточку открывает описание, актёров и трейлер.

## Тюнинг рекомендаций

Все веса — в [`shared/config/recommendation.js`](shared/config/recommendation.js).
В логике компонентов магических чисел нет; тест `F19` это проверяет.

```js
blend:       { tagWeight: 0.62, moodWeight: 0.28, qualityWeight: 0.10 }
signals:     { like: 1.0, favorite: 2.75, dislike: -0.35, match: 1.6 }
exploration: { rate: 0.25, coldStartRate: 0.6, warmupSignals: 25 }
room:        { sharedTagBoost: 1.85, soloTagWeight: 0.55, deckSize: 40 }
```

Эти же значения переопределяются на лету через строку `recommendation`
в таблице `app_config`:

```json
{
  "base": { "exploration": { "rate": 0.2 } },
  "variants": {
    "explore-more": { "exploration": { "rate": 0.35 } },
    "explore-less": { "exploration": { "rate": 0.12 } }
  }
}
```

Вариант выбирается детерминированно по `user_id`, так что A/B-тест не требует
ни релиза, ни фиче-флагов.

## Телеметрия

Три независимых потока — их часто смешивают, и зря:

1. **Исключения кода** → Sentry со структурированным контекстом: уровень,
   модуль (`rooms.create`, `tmdb.proxy`, `auth.telegram-init-data`,
   `swipe.match-calc`), `user_id`, `room_code`, стек, состояние сети.
2. **Сбои логики** (`BIZ`) → Sentry + журнал в `ops_events`. Это то, чего обычный
   error-трекер не видит: комната не найдена (и каким способом искали),
   транзакция свайпа повторилась из-за гонки, TMDB вернул пусто или
   рейт-лимит, Security Rules отклонили запись, `initData` не прошёл подпись.
3. **Продуктовые метрики** → `ops_metrics`; дашборд считает агрегаты SQL-запросом,
   поэтому их можно пересчитать задним числом, а не только копить счётчиками.

Окружения (`dev` / `staging` / `prod`) разделены — локальная разработка не
будит прод-алерты.

Дашборд: **Профиль → Метрики** (нужен `OPS_DASHBOARD_TOKEN`).

## Тестирование

77 проверок в четырёх уровнях, `npm test`:

| Уровень | Файл | Что проверяет |
|---|---|---|
| 1 · Feature Coverage | `tests/tier1-features.test.mjs` | Каждая заявленная возможность: схема тайтла, теги, 5D, комнаты, подпись Telegram, конфиг, артефакты сборки |
| 2 · Boundary & Corner | `tests/tier2-boundaries.test.mjs` | Мусор на входе, null, экстремальные значения, невалидные коды, переполнение профиля, просроченный `initData` |
| 3 · Cross-Feature | `tests/tier3-interactions.test.mjs` | Фильтры ↔ лента, комната ↔ личный вкус, конфиг ↔ поведение движка, обработка ошибок TMDB, контракт HTTP-обёртки |
| 4 · Real-World Workflows | `tests/tier4-workflows.test.mjs` | Полные сценарии: холодный старт → прогрев, комната на двоих с гонкой свайпов, вход по трём типам ссылок, возврат из фона, синхронизация между устройствами |

Гонка свайпов проверяется не в тестах, а там, где она живёт: функция
`record_swipe` берёт блокировку строки комнаты и делает всё одной транзакцией
Postgres. Сценарий «двое свайпают одну карточку» прогоняется прямо в базе —
см. комментарий в `supabase/migrations/20260825090300_room_rpc_functions.sql`.

## Чего нет в MVP (осознанно)

- **Сериалы и аниме.** Только фильмы. Схема к ним готова: `kind` есть в id
  и в модели с первого дня, добавление категории — это новый нормализатор,
  а не миграция хранилища.
- **Собственный CDN постеров.** Только TMDB.
- **Оплата.** Точки расширения заложены: `profiles.access_tier` и
  `profiles.access_stars` существуют, клиенту недоступны на запись и уже
  отражены в политиках — Telegram Stars подключаются без изменения модели данных.
